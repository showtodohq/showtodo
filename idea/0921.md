## 1. 背景与愿景

ShowTodo 的核心定位是 **“公开可围观的 Todo List”**：
- **写的人轻松，看的人有趣**。
- 强调“行动透明”与“社交监督/见证”。

为了让用户更自然地使用 ShowTodo，需要打破传统“必须手动打开网页打字”的单一闭环：
1. **开发者/创作者入口**：代码推送到 GitHub、推文发到 X 时，能无缝映射与展示 Todo。
2. **AI Native 协同**：在让 AI Agent（Claude Desktop, Cursor, Antigravity, Open-WebUI 等）跑长时间任务时，AI 能自动将阶段目标与进展上报至 ShowTodo，让全世界围观 AI 驱动的建造过程。
3. **心流捕获（Capture at the speed of thought）**：灵感转瞬即逝，通过手机物理按键（如 iPhone Action Button、Android 侧键/快捷磁贴），实现 0.5 秒直接录入或语音转办。

## 2. 社交平台接入与生态传播（GitHub & X/Twitter）

### 2.1 社交登录（OAuth 2.0 / OIDC）

当前系统采用“填 email 自动创建账号”的极简模式（见 `idea/0826.md`）。随着社区发展，引入 GitHub 与 X (Twitter) 登录是强化开发者/极客属性的关键。

#### 流程与机制
- **GitHub OAuth**：
  - 范围（Scope）：`read:user`, `user:email`。
  - 获取：`handle`（直接对应 GitHub username）、`avatar`（GitHub 高清头像）、验证邮箱。
- **X (Twitter) OAuth 2.0 + PKCE**：
  - 范围（Scope）：`tweet.read`, `users.read`, `offline.access`。
  - 获取：`handle`（X 账号 @handle）、`avatar`。
- **账号合并策略**：
  - 若 OAuth 返回的 verified email 与系统内已存在的 User.email 匹配，则自动关联至同一账号，补全或更新 avatar 与 handle。
  - 支持解耦多凭据绑定，避免单点故障。

### 2.2 多平台内容分享与社交裂变

#### A. 极简 Web Intent 分享（零外部依赖）
- **X (Twitter) Intent**：
  ```
  https://x.com/intent/tweet?text={encoded_content}&url={todo_url}&hashtags=showtodo,buildinpublic
  ```
  - 点击“分享至 X”即刻调起 X 客户端或网页发推窗口，预填 Todo 内容与围观链接。

#### B. 动态社交预览卡片（Open Graph / Twitter Card）
- 围观链接在 X、Discord、Telegram、微信展开时，必须具备极高信噪比的视觉卡片：
  - 显示：Todo 标题、当前状态徽标（进行中 / 已完成）、作者昵称与头像、最新进展条数、围观 Reaction 计数。
  - 技术方案：SvelteKit 服务端生成 SVG/PNG（或集成 `@vercel/og`），提供 `/api/og/todo/[shortId]` 动态渲染端点。

#### C. GitHub 深度联动（后续扩展）
- **GitHub Action / Webhook 触发**：提交 Commit 包含 `closes showtodo#<shortId>` 或 Issue 变更时，自动调用 ShowTodo API 标记该 Todo 为 `done`。
- **个人 GitHub Profile 动态**：提供动态 Markdown/SVG Widget，支持用户贴在 GitHub Readme 上（如 `[![ShowTodo](https://showtodo.io/badge/user.svg)](...)`）。

## 3. 开放 MCP（Model Context Protocol）与 AI 任务跟踪

### 3.1 核心价值与应用场景

现代开发者已普遍使用 AI Agent（如 Cursor, Claude Desktop, Antigravity, Windsurf, Open-WebUI 等）编写代码或调研方案。
在执行复杂的长链条任务时：
1. **用户下发宏观需求**：“请帮我设计并重构支付模块，同时在 ShowTodo 上公开你的拆解进度。”
2. **AI 自主拆解与立项**：AI 规划出 3~5 个关键步骤，调用 ShowTodo MCP 工具，直接在平台创建一组公开 Todo。
3. **执行与动态播报**：
   - AI 开始执行某步骤时，将 Todo 状态置为 `in_progress`。
   - AI 阶段性产出时，调用 `append_todo_activity` 写入进展摘要（例如：“已完成单元测试，涵盖 8 个核心用例”）。
   - 最终步骤完成，标记为 `done`。
4. **围观效应**：社区好友或协作伙伴通过公开链接，实时围观“AI 正在做什么”以及“进度到了哪一步”。

### 3.2 技术架构方案

#### A. MCP Server 交付形态
1. **Remote MCP Server（推荐主推方案）**：
   - 协议：基于 **SSE (Server-Sent Events) + JSON-RPC**（MCP 官方支持的远程传输标准）。
   - 接入方式：ShowTodo 部署 `/api/mcp/sse` 端点，用户只需在 AI 客户端配置：
     ```json
     {
       "mcpServers": {
         "showtodo": {
           "url": "https://showtodo.io/api/mcp/sse",
           "headers": {
             "Authorization": "Bearer YOUR_SHOWTODO_API_TOKEN"
           }
         }
       }
     }
     ```
   - 优势：零安装、零本地 Node.js 运行环境依赖，云端多客户端无缝漫游。
2. **Local Stdio Wrapper（补充方案）**：
   - 发布轻量 npm 包 `@showtodo/mcp-server`，供仅支持 stdio 的本地客户端使用，内部直连 ShowTodo REST API。

#### B. API Token 鉴权设计
- 在用户设置页增加“开发者凭证 / API Keys”管理。
- 采用带有前缀的密钥格式（如 `st_live_...`），数据库存储加盐哈希。
- 权限范围（Scopes）：`todo:read`, `todo:write`, `activity:write`。

#### C. MCP Tools 定义清单

| 工具名称 (Tool) | 参数 | 说明 | 对应领域操作 |
|---|---|---|---|
| `create_todo` | `content` (必填), `note` (选填), `category` (选填), `isNotePublic` (默认 true), `dueDate` (选填) | 创建一条新的公开待办 | `createTodo` |
| `update_todo_status` | `shortId` / `id` (必填), `status` (`pending` \| `in_progress` \| `done` \| `abandoned`) | 切换待办状态，自动生成状态变更动态 | `updateTodoStatus` |
| `append_todo_activity` | `shortId` / `id` (必填), `content` (必填), `type` (`progress_note` \| `status_change`) | 为指定 Todo 追加实时进展/执行日志（对齐 `todoActivities` 表） | `addActivity` |
| `list_my_todos` | `status` (选填), `limit` (默认 10) | 获取自己近期的待办列表，使 AI 具备自我感知与上下文追踪能力 | `listTodosByAuthor` |
| `get_todo_detail` | `shortId` / `id` (必填) | 获取特定 Todo 的详细信息及历史活动轨迹 | `getTodoById` |

## 4. 移动端物理按键与极速录入方案调研（iOS & Android）

移动端录入的核心痛点：**心流中断**。  
若需要“掏出手机 → 面容解锁 → 翻找桌面图标 → 等待 App 启动加载 → 寻找输入框 → 键盘敲字”，大部分瞬时灵感就会丢失。

### 4.1 iOS 平台实现路径

#### 方案 1：iPhone Action Button（操作按钮，iPhone 15 Pro 及以上首选）
- **技术底层**：iOS 系统支持将侧边 Action Button 直接绑定到一个特定的 **“快捷指令（Shortcuts）”**。
- **链路实现**：
  1. **纯后台无感极速提交（无需前台打开 App，最快 < 1秒）**：
     - Action Button 触发快捷指令：
       - ① 弹窗“听写文本（Dictate Text）”或“提示输入（Ask for Input）”。
       - ② 获取文本后，快捷指令通过“获取 URL 内容（Get Contents of URL）”直接 POST 到 `https://showtodo.io/api/v1/todos`（携带个人 API Token）。
       - ③ 触发系统触觉反馈（Haptic Feedback），静默完成。
  2. **快速跳转打开专用录入页**：
     - 快捷指令执行：打开 URL Scheme `showtodo://quick-add` 或通用链接 `https://showtodo.io/quick-add`。
     - 页面仅展示一个自动聚焦的 Input 输入框，打字后回车即走。

#### 方案 2：Back Tap（轻点背面，iPhone 8 及以上全系通用）
- **路径**：系统设置 → 辅助功能 → 触控 → 轻点背面（双击 / 三击）。
- 映射至上述同一套 ShowTodo 快捷指令。覆盖所有无 Action Button 的 iPhone 机型。

#### 方案 3：iOS 18 锁屏快捷组件与控制中心磁贴
- iOS 18 开放锁屏底角两个快捷按键（原生手电筒/相机位置）以及控制中心的自由替换。
- 允许配置自定义 Controls 或直接唤起快捷指令，在锁屏界面单手一键呼出。

---

### 4.2 Android 平台实现路径

#### 方案 1：快捷设置磁贴（Quick Settings Tile）
- **技术底层**：Android 原生 `TileService` API。
- **链路实现**：
  - 用户下拉状态栏，点击 ShowTodo 磁贴。
  - 直接弹出一个浮动/透明的 Dialog 输入框（或悬浮 Activity），不切走当前用户所在的应用界面，录入完毕点击提交即消失。

#### 方案 2：物理按键映射（电源键 / 侧键 / 音量键）
- **厂商原生定制能力**：
  - **三星 One UI**：设置 → 高级功能 → 侧边键（双击侧边键可直接绑定启动任意 App 或特定的 App 快捷方式 Shortcut）。
  - **小米 MIUI / HyperOS**：设置 → 更多手势提示 → 双击电源键 / 快捷手势绑定应用。
- **全局辅助功能监听（独立原生 App 路径）**：
  - 利用 `AccessibilityService` 监听物理按键组合（如连按两次音量减键），拦截按键事件呼出 ShowTodo 悬浮录入窗口。
  - （或用户使用通用工具如 Key Mapper，将按键映射至 ShowTodo 的 Shortcut Intent）。

#### 方案 3：App Shortcuts & 锁屏小部件
- Android 原生 Static / Dynamic Shortcuts（长按图标呼出的快捷菜单项），用户可将其拖动并固化到桌面。
- Android 锁定屏幕快捷方式配置。

### 4.3 客户端技术形态权衡（PWA vs 混合原生）

| 维度 | 方案 A：Web PWA + iOS/Android 原生快捷指令与快捷方式 | 方案 B：轻量混合原生包（Capacitor / Tauri Mobile） |
|---|---|---|
| **开发成本** | 极低（直接复用当前 SvelteKit 代码库与 API，零额外维护负担） | 中等（需配置 iOS/Android 编译环境、打包、签名与上架） |
| **物理按键支持** | **完全满足**（iOS 通过快捷指令绑定 Action Button/轻点背面；Android 通过 Shortcut 绑定侧键） | **完全满足**，且可自建 Background Service、系统浮窗与磁贴 |
| **离线输入体验** | 依托 ServiceWorker 与 Cache API | 原生本地 SQLite 存储，自动后台重试同步 |
| **发布与分发** | 网页即开即用，提供“一键安装快捷指令 / 添加到主屏幕”指引 | 需通过 App Store / Google Play / 国内应用商店审核 |
| **阶段建议** | **前期首选**：快速验证极速录入闭环，极大降低研发周期 | **后期演进**：当用户规模扩大、需要原生通知与系统级常驻磁贴时采用 |

## 5. 数据架构与领域模型演进（DDD 视角）

结合已有 schema（`src/lib/server/db/schema.ts`），为支撑上述能力，未来规划的新增模型设计建议：

### 5.1 领域实体扩充

```
[User 聚合根]
  │
  ├── 1:N ──→ [OAuthAccount (第三方绑定)]
  │             ├── provider: 'github' | 'x' | 'google'
  │             ├── providerUserId: string
  │             └── profileData: jsonb
  │
  ├── 1:N ──→ [ApiKey (开放 API / MCP 授权凭据)]
  │             ├── keyHash: string (加盐哈希)
  │             ├── keyPrefix: string ('st_live_...')
  │             ├── name: string
  │             └── scopes: string[]
  │
  └── 1:N ──→ [Todo 实体]
                │
                └── 1:N ──→ [TodoActivity 实体] (已有)
                              └── (支持 MCP 自动录入的阶段性进展)
```

## 6. 落地演进路线（Roadmap）

### 阶段一：开放核心能力与极速录入验证（MVP）
- [ ] **开放 API & Token 认证**：
  - 设计 `/api/v1/todos` RESTful 端点（创建、更新状态、追加进度）。
  - 用户个人中心增加简易 API Token 生成与撤销能力。
- [ ] **极速录入链路打通**：
  - 制作官方 iOS 快捷指令（Shortcuts）分享链接，指导用户将 Action Button / 双击背面一键绑定 ShowTodo。
  - Web 端提供极简录入专用页面 `/quick-add`（零多余装饰，纯键盘焦点，瞬间提交）。

### 阶段二：MCP 智能体生态构建
- [ ] **ShowTodo MCP Server（SSE 端点）开发**：
  - 在 SvelteKit 服务端实现标准 SSE JSON-RPC MCP 接口。
  - 封装 `create_todo`, `update_todo_status`, `append_todo_activity`, `list_my_todos` 4 个核心工具。
- [ ] **AI 客户端对接与文档引导**：
  - 发布 Cursor / Claude Desktop / Antigravity 的一键配置教程。
  - 验证 AI 长任务自动报单与进度实时追踪闭环。

### 阶段三：社交身份互联与病毒式传播
- [ ] **社交登录集成**：
  - 接入 GitHub OAuth 与 X (Twitter) OAuth 2.0。
  - 自动同步个人 profile、头像与 handle 认证标志。
- [ ] **高品质社交卡片与一键推特分享**：
  - 开发动态 OpenGraph 图片生成服务。
  - Todo 详情页与个人主页提供“一键发布进展至 X”的快捷交互。
