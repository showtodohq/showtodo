# 数据模型设计（MVP v1）

## 项目定位

公开可围观的 Todo List。所有人都可以发布 todo，所有 todo 对任何人可见，不可隐藏。

## 核心原则

- **极简 Todo**，不做 Task/Plan 那样的重型项目管理
- 写的人轻松（最少只填 email + content），看的人有趣
- MVP 无注册登录，WordPress 评论模式：填 email 发布，自动建账号

## 数据模型

### User

| 字段 | 类型 | 说明 |
|---|---|---|
| id | string | 唯一标识 |
| email | string | 必填，唯一，登录凭证 |
| nickname | string | 默认为 email `@` 前的部分，后续 Google 登录可更新 |
| avatar | string \| null | 头像 URL，默认 null。前端逻辑：有值则显示，无值则用 DiceBear 以 nickname 为 seed 自动生成 |
| createdAt | datetime | 创建时间 |
| updatedAt | datetime | 最后修改时间 |

### Todo

| 字段 | 类型 | 说明 |
|---|---|---|
| id | string | 唯一标识 |
| content | string | 内容（必填，永远公开） |
| note | string \| null | 备注/描述（可选） |
| isNotePublic | boolean | 备注是否公开（默认 true）。隐藏时围观者不可见 |
| category | string \| null | 分类 ID，对应静态配置（可选） |
| authorId | string | 关联用户 |
| status | enum | pending \| in_progress \| done \| abandoned |
| startDate | date | 计划开始日期（默认创建时间） |
| dueDate | date \| null | 计划截止日期（默认 null） |
| createdAt | datetime | 创建时间 |
| updatedAt | datetime | 最后修改时间 |

#### 状态流转

```
pending（待办）
  ├──→ in_progress（进行中）
  │       ├──→ done（已完成）
  │       └──→ abandoned（已放弃）
  ├──→ done（已完成）
  └──→ abandoned（已放弃）
```

时间戳方案采用极简方式：只用 createdAt + updatedAt，不为每个状态单独设时间戳。后续如需完整状态变更历史，可加 TodoStatusLog 表。

### Reaction

| 字段 | 类型 | 说明 |
|---|---|---|
| id | string | 唯一标识 |
| todoId | string | 关联 Todo |
| emoji | string | 反应 emoji（👀🔥💪👏） |
| userId | string | 关联用户 |
| createdAt | datetime | 创建时间 |

## 发布流程（MVP）

```
用户填写：email + content（+ 可选字段）
  ↓
后端：email 在 User 表中存在？
  ├── 是 → 用该 user ID 作为 authorId
  └── 否 → 自动创建 User（nickname = email.split('@')[0]）
  ↓
创建 Todo
```

## 头像方案

- 使用 DiceBear（https://www.dicebear.com/）
- 前端逻辑：`user.avatar ? user.avatar : DiceBear(user.nickname)`
- 纯 URL 调用，不存库，不污染数据模型

## 认证演进路径

1. **MVP**：无注册登录，填 email 即发布
2. **后续**：对接 Google OAuth，按 email 匹配已有账号，自动更新 nickname 和 avatar

## 设计决策记录

- **为什么不用 Task/Plan 模型**：项目定位是轻量公开 todo，不是项目管理工具
- **为什么状态不单独设时间戳**：MVP 阶段 updatedAt 足够，后续可加 StatusLog 表
- **为什么分类用静态配置**：MVP 简化，后续可扩展为动态分类（搬到数据库即可）
- **为什么分类用颜色不用 emoji**：色块标签更整洁统一，辨识度更高
- **为什么备注可隐藏**：在"todo 永远公开"的前提下，允许用户保护部分隐私信息
